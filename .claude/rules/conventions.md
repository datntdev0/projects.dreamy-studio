# Coding Styleguide

- RULE-001: No member comments, keep code self-explanatory through clear naming and structure.
- RULE-002: No linter and formatter issues returned by `pnpm lint` and `pnpm format` commands.
- RULE-003: Avoid nested functions by extracting them into separate functions.
- RULE-004: Avoid duplicated code by extracting common logic into reusable functions or modules.

# Commit Message Conventions
- Commit message format: `<type>(<scope>): <summary>`. The summary must not exceed 100 characters.
