# verify

Visual verification of the desktop app against the prototype, using Playwright.

The prototype in `_proto/1.library` rendered with its mock data is the **baseline**. The real app, started with a fixture built from the same mock data, is compared against it **per layout panel**. The common components (titlebar, railbar, statusbar) have one spec each (`tests/layout-{titlebar,railbar,statusbar}.spec.ts`, baseline `baseline/layout/<panel>.png`); every screen spec compares only its own panels (explorer, crumbs, toolbar, content, inspector). The tab bar is not compared: the prototype starts with the Images tab, while the app always starts with Home and Collections & tags, so the two tab sets differ by design of the harness. A failing panel names the component that differs, and the reporter ranks them.

## How it works

- The app takes `--data-dir <path>`. Everything it stores (application database, logs) goes there instead of `%LOCALAPPDATA%\DreamyStudio`.
- `src/fixture` starts the app on a scratch data dir and loads `_proto/1.library/js/library-data.js` through the app's own commands: 4 collections, 17 images, 8 sounds, 8 videos and 8 prompts, with the prototype's tags, rights and dates. The result is cached in `_output/verify/fixture`.
- The same fixture imports the novels of `_proto/shared/js/novel-data.js` (`novel_package_import`, or `novel_create` for a novel with no package): 4 novels, 23 chapters, with the prototype's names, tags and dates, and the translated/analyzed chapters of the sample novel. Each package is built on the fly from `_proto/shared/assets/novel/<pack>/` (`manifest.json`, `chapters/*.txt`, optional `cover.png`). `pnpm fixture` and every Playwright run (`pnpm baseline`, `pnpm test`) first regenerate `_proto/shared/js/novel-corpus.js` (chapter titles, word counts and text, read by the prototype) from those packages, so the prototype and the app never disagree about a package you edited.
- Each run copies the fixture to `_output/verify/run`, starts the app on `_output/verify/run/data`, and attaches Playwright to the WebView2 over CDP.
- Two Playwright projects run the same spec: `prototype` (Edge, `file://`) and `app` (the desktop app).

## Prerequisites

- Windows with the WebView2 runtime and Microsoft Edge.
- `backend/.venv` set up, because opening a workspace starts the Python backend.
- Network access: the UI loads the Geist font from Google Fonts. The run fails early if it did not load.
- A debug app build with the frontend embedded: `pnpm build:app`. Set `DREAMY_EXE` to use another executable. `pnpm start:proto` (`tauri dev`) overwrites the same executable with a dev build that loads `http://localhost:1420`; after it, the app window shows "localhost refused to connect" and every app test fails with "the app did not open a page". Run `pnpm build:app` again.

## Commands

| Command | What it does |
|---|---|
| `pnpm install` (repo root) | Installs Playwright (no browser download is needed). |
| `pnpm build:app` | Builds `_output/desktop/target/debug/dreamy-studio.exe`. |
| `pnpm fixture` | Rebuilds the fixture. Run it after a schema, prototype data or novel package change. |
| `pnpm baseline` | Renders the prototypes (library and novel) and writes `baseline/` (only changed images). |
| `pnpm test` | Compares the app with `baseline/` (library and novel) and prints the ranking. |
| `pnpm test:prototype` | Compares the prototype with its own baseline, to prove the baseline is stable. |
| `pnpm seed:proto` (repo root) | Rebuilds the debug app, then wipes and reseeds `_output/verify/proto` with the prototype data (library and novels). Run it after a prototype data change. |
| `pnpm start:proto` (repo root) | Runs the app in dev mode on `_output/verify/proto`. It never seeds; it stops with a hint if the dir is empty. |
| `pnpm test tests/library-images.spec.ts` | Any command above takes Playwright arguments, e.g. one spec file. There is one per screen (plus the three layout specs above): `tests/library-{images,sounds,videos,prompts,collections,collection}.spec.ts` and `tests/novel-{novels,chapters,reader}.spec.ts`. |
| `pnpm report` | Opens the HTML report with expected, actual and diff images. |

`baseline/<screen>/<state>/<panel>.png` is generated by `pnpm baseline` and git-ignored. The states of a library screen are `overview`, `selected`, `list-overview`, `list-selected` and, for images, sounds and videos, `preview` (the preview dialog). The novel screens are `novels/grid`, `novels/list`, `novel/chapters` and `novel/reader`. The novels screens compare the inspector after one click on the sample novel; with nothing selected the inspector shows only "Choose a novel to see its properties." (the prototype and the app have no overview panel). `novel/chapters/preview` is the Add chapter dialog. `novel/chapters` includes the Add chapter button in the toolbar and the delete action of every row. `_output/verify/diff-summary.json` holds the ranking of the last run.

`start:proto` starts the Angular dev server on port 1420, so stop any other `pnpm start` first. Open the "Dreamy Studio" entry in the recent list.

## Language

The prototype and the app are compared in English: the prototype's default language is English, and the app runs with `dreamy-studio.language=en` and the `en-US` locale. The two Vietnamese sample novels ("Những Con Sóng Không Tên" and "Gió Muộn Trên Đồi Thông") keep their Vietnamese titles and text because they are Vietnamese-language content, not interface text.

## Known gaps

- The prototype videos are fragmented MP4 files with no `mehd` box, so `video_probe.rs` cannot read their duration. The fixture patches the `mvhd` duration of its staged copies and sets `fps` from the prototype data.
- The status bar shows the workspace path, which differs per machine. The path text is hidden (`visibility: hidden`) before every comparison, so it is neither in the screenshot nor in the aria snapshot.
- The prototype runs in headless Edge, where Playwright hides scrollbars; the app run uses CDP `Emulation.setScrollbarsHidden` in `src/studio.ts`, so both sides lay out without a scrollbar gutter.
